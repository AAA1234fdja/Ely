# Idiomas de la interfaz

Ely Cowork habla **14 idiomas** en toda la interfaz: navegación, chat, IDE,
terminal, panel inferior, extensiones, ajustes y textos dinámicos del backend.

## Los 14 y su orden

El selector **no** sigue el orden en que se pidieron los idiomas. Se ordenan
**alfabéticamente por su autónimo** (el nombre en su propia lengua), con el
bloque latino primero y después griego, cirílico, devanagari y CJK. Es la
convención que usan los sistemas que no quieren privilegiar ningún idioma:
nadie depende del inglés ni del español para encontrar el suyo.

## Arquitectura

```
frontend/js/i18n.js          motor + diccionario base D (es, en) + LANGS
frontend/js/locales/<id>.js  un paquete por idioma, cargado bajo demanda
IDE/i18n-core.json           las 415 claves del núcleo mínimo obligatorio
```

- **Español es el origen.** El diccionario `D` guarda pares `[es, en]`; el
  backend y muchas vistas generan texto en español.
- **Inglés no necesita paquete**: es la segunda columna de `D`.
- **Los otros 12 son paquetes** que se registran con `I18N.register(id, dict)` y
  se descargan por HTTP sólo cuando se eligen (`js/locales/<id>.js?v=<versión>`).
  Arrancar el IDE en alemán descarga un único fichero, no doce.
- **Cadena de resolución**: paquete del idioma → inglés → español. Nunca se
  muestra una clave cruda ni un texto vacío. Hoy ningún idioma llega al
  fallback (los 12 paquetes están completos), pero la cadena sigue viva y se
  prueba borrando una clave en caliente: garantiza que un paquete parcial
  futuro —o una clave nueva añadida a `D`— nunca muestre español a un usuario
  que eligió japonés.

### API

| Método | Qué hace |
|--------|----------|
| `I18N.langs` | catálogo de los 14 (`id`, `name`, `en`, `htmlLang`, `script`, `note`) |
| `I18N.lang()` / `meta(id)` | idioma activo / sus metadatos |
| `I18N.t(key)` | traduce una clave con la cadena de fallback |
| `I18N.tr(texto)` | traduce un texto suelto en español (frases y patrones) |
| `I18N.ensure(id)` | carga el paquete si falta; devuelve una `Promise` |
| `I18N.setLang(id)` | carga el paquete **y luego** cambia el idioma (sin parpadeo) |
| `I18N.register(id, dict)` | registra un paquete |
| `I18N.dict(id)` | el paquete registrado, o `null` |
| `I18N.coverage(id)` | `{translated, total, pct}` reales |
| `I18N.phrasesFor(id)` | mapa es→idioma para el traductor de DOM |
| `I18N.apply(root)` | repasa el DOM ya renderizado |

Al cambiar el idioma se emite `ely:langchange`; el motor actualiza
`<html lang>`, repasa el DOM y la app repinta la vista activa. Las extensiones
reciben el nuevo idioma por su canal (`ely.env.language`).

### Textos dinámicos

Los mensajes con números que llegan del backend (`hace 5 min`,
`11 configurados`, `Línea 12, columna 4`, `$1 endpoint(s) respondieron`…) se
reconocen con 37 patrones. Cada patrón tiene una clave `pat.*` con su plantilla,
de modo que un paquete traduce el orden de las palabras y no sólo las palabras:

```js
"pat.agoMin": "vor $1 Min."      // de
"pat.agoMin": "$1 分前"           // ja
"pat.agoMin": "$1 мин назад"     // ru
```

Los marcadores `$1`, `$2` se conservan siempre (hay un test que lo comprueba en
los 12 paquetes), igual que los de llave (`{n}` en «se eliminarán {n}
conversaciones»), el marcado en línea (`<b>` en la descripción del almacén) y
las cifras.

## Cobertura: 745/745 en los 14

El diccionario completo tiene **745 claves** y **los 12 paquetes las traen
todas**: 8.940 cadenas traducidas, más el español y el inglés de `D`. No queda
ningún idioma a medias.

| Bloque | Claves | Qué cubre |
|--------|-------:|-----------|
| Núcleo (`IDE/i18n-core.json`) | 415 | navegación, cabecera, conexión, ajustes, panel inferior, menús, chat, extensiones |
| Accesibilidad (`a11y.*`) | 120 | lector de pantalla, señales sonoras, contraste, tipografía, teclado, 19 avisos `a11y.sig.*` y 21 atajos `a11y.k.*` |
| IDE (`ide.*`) | 60 | guías de bienvenida, transformaciones de texto, estados vacíos, SCM |
| Chat y almacén (`chat.*`, `ls.*`) | 56 | menús del compositor, proyectos, borrados, almacén local |
| Descripciones y extensiones (`navdesc.*`, `ext.*`) | 38 | descripciones de la navegación, permisos, instalación, red |
| Visores (`vw.*`, `cw.*`) | 15 | visor de archivos y chat flotante |
| Patrones dinámicos (`pat.*`) | 37 | plantillas con `$1`/`$2` para el texto que llega del backend |
| Avisos de idioma (`set.lang*`) | 4 | cobertura real y notas de latín/vendergood |
| **Total** | **745** | |

El núcleo se conserva como **mínimo obligatorio** en `IDE/i18n-core.json`: un
paquete nuevo puede empezar por ahí y funcionar, pero los tests exigen la
cobertura completa antes de darlo por bueno.

**No se finge cobertura.** Ajustes muestra el porcentaje real calculado sobre
`D`; al 100 % el aviso «Lo que falte se muestra en inglés» desaparece, y sólo
queda la nota de lengua experimental en latín y vendergood.

Auditoría real (`i18n-audit`, app servida + jsdom, 18 rutas + chat + IDE +
ajustes, revisando nodos de texto y atributos `placeholder`/`title`/`aria-label`):

| Idioma | Textos en español encontrados |
|--------|-------------------------------|
| en, el, ru, hi, zh, ja | **0** |
| de, fr, it, pt, pl, la, vg | sólo falsos positivos del detector |

El detector busca palabras funcionales españolas (`de`, `la`, `en`, `clave`…) y
morfología inequívoca. En alemán marca «schließ**en**», en francés «**la**
connexion» y «**un** projet», en italiano «**con** permessi», en polaco
«Rozw**ó**j», en latín «**De** nobis» y en vendergood «File **de** texte»: son
palabras correctas del idioma destino. Revisadas una a una en los 14 idiomas,
ninguna es español sin traducir. Los idiomas de otra escritura (griego, ruso,
hindi, chino y japonés) son la señal fiable del detector, y dan 0.

### Teclas y cifras

Los atajos se rotulan como en el teclado físico de cada idioma, igual que hace
VS Code: alemán `Strg`/`Umschalt`, francés `Maj`/`Échap`/`Entrée`, italiano
`Invio`/`Esc`. El resto usa `Ctrl`/`Shift`/`Enter`. El detector de literales
normaliza esos alias antes de comparar, de modo que la tecla sigue comprobándose
aunque cambie su nombre.

Las cifras no se traducen nunca; la unidad sí puede (chino «32 像素», japonés
«32 px»). El latín usa numeración arábiga —`14 linguae`, `32 px`, `Sidis, 1909`—
porque en una interfaz técnica `XIV` o `MCMIX` obligan a calcular en vez de leer.

## Latín y vendergood

Los dos se piden explícitamente y los dos se entregan, pero **marcados**.

**Latín (`la`)** — no existe vocabulario técnico normalizado. Se usa el léxico
habitual de la Vicipaedia y de la neolatinitas informática: `lima` (archivo),
`theca` (carpeta), `inceptum` (proyecto), `persona` (perfil), `computatrum`,
`terminale`, `exitus`. Ajustes lo avisa: *«Traducción experimental: el latín no
tiene vocabulario técnico normalizado»*.

**Vendergood (`vg`)** — es la lengua construida que William James Sidis describió
hacia 1909 en su *Book of Vendergood*. Está documentado que la basó en el latín
y en lenguas romances y germánicas, que tenía ocho modos verbales y numeración
duodecimal. **No hay corpus público de vocabulario**: el manuscrito no está
publicado ni existe diccionario consultable.

Por eso el paquete **no se presenta como vendergood auténtico**. Es una
aproximación experimental: formas derivadas de raíces latinas/romances con
morfología simplificada, coherentes con la base documentada. Cada cadena es una
propuesta, no una atestiguación, y así lo dicen la cabecera del fichero y el
aviso de Ajustes. Su `html lang` es `art-x-vendergood`, la etiqueta BCP-47
correcta para una lengua construida sin código ISO. Si algún día se publica el
corpus original, `locales/vg.js` es el único fichero que hay que sustituir.

## Tipografía por escritura

La pila de fuentes incluye respaldos para devanagari (`Noto Sans Devanagari`,
`Nirmala UI`, `Kohinoor Devanagari`, `Mangal`) y CJK (`Noto Sans SC`,
`Microsoft YaHei`, `PingFang SC`, `Hiragino Sans`, `Yu Gothic`, `Meiryo`,
`Noto Sans JP`), también en la monoespaciada. Griego y cirílico los cubren las
fuentes latinas del sistema.

Además hay reglas por `<html lang>`: más altura de línea en hindi para que las
marcas vocálicas no se recorten en las filas densas del árbol, y un interletrado
ligeramente mayor en chino y japonés.

## Extensiones

El manifiesto `ely-extension.json` acepta `l10n` con **cualquier** idioma:

```json
"l10n": {
  "en": { "name": "Word count", "description": "Counts words" },
  "de": { "name": "Wortzähler", "description": "Zählt Wörter" },
  "ja": { "name": "単語数", "description": "単語を数えます" }
}
```

El backend devuelve el mapa completo y el host elige el idioma activo, con
fallback a inglés y después al español del manifiesto. Dentro de la extensión:

```js
const ely = acquireElyApi();
ely.l10n("Hola", "Hello");                       // forma clásica de 2 argumentos
ely.l10n({ es: "Hola", en: "Hello", de: "Hallo", ja: "こんにちは" });  // mapa
```

## Cómo ampliar un paquete

1. Abre `frontend/js/locales/<id>.js`.
2. Añade la clave con su traducción **en los 12 paquetes**: la fuente de verdad
   es `D` (`frontend/js/i18n.js`) y los tests exigen cobertura completa. El
   orden recomendado es el de `IDE/i18n-core.json` para el núcleo.
3. Para texto estático que no es una clave, añade la entrada al mapa `extra`
   del paquete (`"Texto en español": "Traducción"`).
4. Comprueba:

```bash
python3 -m unittest discover -s CLI/tests            # 299 tests
node --check IDE/frontend/js/locales/<id>.js
# con `ely serve` en marcha:
node /tmp/ely-harness/i18n-locales.mjs               # 193 comprobaciones
ELY_LANG=<id> node /tmp/ely-harness/i18n-audit.mjs   # restos en español
```

Los tests fallan si un paquete pierde **cualquiera** de las 745 claves, duplica
una clave, deja un valor vacío, inventa una clave que no existe en `D`, pierde
un marcador `$1` o `{n}`, pierde marcado en línea, traduce un literal técnico
(`.ely/tasks.json`, `network:<host>`, `planeado/`…) o cambia una cifra. También
comprueban que cada paquete escribe de verdad en su alfabeto (más de 300 claves
en griego, cirílico, devanagari o CJK) y que latín y vendergood siguen
declarando su carácter experimental.
